## 2. Presence -- First Live Calibration

### 2.1 Order of operations
Question: should live detection run first, to detect a setup change, and only
then calibrate? Answer: no. The in-session monitor only notices a change when
someone sits in a front seat for ~3 min and the front row has moved > 10 cm; it
cannot see an empty cabin, back-row-only changes, tilts or smaller shifts, and
the zones may be wrong before it notices. The self-test (now `check`) is the
startup check. For this first time, `calibrate` came first, because the
calibration on disk was built from the Sep 25 recordings, not measured live.

### 2.2 Calibration result
```
front  measured 0.994 m   training 0.731 m   -> zone shift +4 bins (+29 cm)
back   measured 1.791 m   training 1.429 m   -> zone shift +4 bins (+29 cm)
seat 1 1.027 m (spread 6 cm)   seat 2 0.977 m (2 cm)
seat 3 1.804 m (1 cm)          seat 4 1.753 m (6 cm)
motion threshold 5.94 (model default 7.77)
receiver noise   sensor 1 -15.3 dB, sensor 2 -15.8 dB   (Sep 25: -14.8 / -15.8)
validation       empty 0% flagged; seats 1, 2 front 100%; seats 3, 4 back 100%, front 0%
```
The setup moved ~25 cm since Sep 25 (front row was 0.77 m then), both rows by a
similar amount -- consistent with the radar or the whole seating block moving.
Receiver noise matched Sep 25, so the hardware was unchanged. A 29 cm shift is
beyond the 21 cm case tested with recalibration in simulation, and occupants
now sit ~1 m away (~5 dB weaker), so the independent self-test mattered.

### 2.3 Self-test
```
PASS  empty    EMPTY after 4 s
FAIL  3        occupied 35/35; front row wrongly shown on 100%
PASS  4, 1, 2  occupied in every decision, rows correct
FAIL  empty    EMPTY after 46 s; not EMPTY for the final 20 s
```
The user reported disturbances (people nearby) during seat 3 and the final
empty step. An alternative explanation was kept open: the calibrated motion
threshold (5.94) is more sensitive than the default, so movement 2.5 m away
could hold OCCUPIED. Rerun of just those steps with nobody moving:
```
PASS  3        occupied in 26/26 decisions; front row - ok; back row Y 100%
PASS  empty    EMPTY after 47 s
```
Disturbances confirmed; the calibrated motion threshold is fine. Setup declared
ready for live use.

## 3. Faster Daily Routine

### 3.1 Where the time went
| | before | floor |
|---|---|---|
| live start-up | ~33 s | 30 s window + ~2.5 s radar start |
| self-test | ~7.5 min | two 100 s empty steps, 45 s per seat |
| calibration | ~4.5 min | 60 s empty, 45 s per seat |
| EMPTY after leaving | ~75 s | window + safety hold (by design) |

About 30 s per seat is a physical floor: one analysis window, the time needed
to see a still person breathe.

### 3.2 Calibrating seats in pairs -- tested and rejected
Measured on the v3 recordings, compared with single-seat captures:

| pairing | row position error |
|---|---|
| front + back occupant (seats 1+4, 2+3) | front +5.1 cm; **back row read 0.911 m instead of 1.525 m** (locked onto front leakage) |
| two in one row (1+2, 3+4), v3 | front **+21.1 cm**, back +5.5 cm |
| two in one row, v2 | front +1.7 cm, back +11.6 cm |

Two bodies in one row blur into one peak that can land anywhere between them.
Calibration stays one person per seat.

### 3.3 Built -- `x7_presence_setup.py`
* **`check` (new, the daily routine, ~4 min):** one pass -- empty 45 s, seats
  3, 4, 1, 2 at 35 s -- scored live against the current calibration while a
  fresh calibration is computed from the same recordings.
  - setup unchanged -> keep calibration, `>>> PASS -- go live`
  - setup moved -> replay the recordings with the new calibration; if it
    passes, adopt it (`>>> RECALIBRATED`), keep the old one as
    `models/presence_calib_prev.json`
  - unchanged but a step failed -> FAIL, "a disturbance or real problem, not a
    moved setup"
* **`selftest` quick by default (~4 min):** empty 45 s + four seats at 35 s.
  `--full` keeps the long version (100 s empties, 45 s seats, `--all-seats`,
  final occupied -> EMPTY clearing test, ~8.5 min).
* **`--steps`:** rerun chosen steps, e.g. `--steps 3 empty`; every failed
  report prints the rerun command.
* **`calibrate` shorter (~3 min):** empty 40 s, seats 30 s.
* Rows are judged once the 30 s window holds only the step's own data; health
  warnings fail a step.

### 3.4 Built -- `x7_presence_zone.py`
* During warm-up, motion (someone arriving) now shows `OCCUPIED (motion)
  front ? back ?` immediately instead of `UNKNOWN`; rows appear after 30 s.
  EMPTY is still never claimed before the window is full.

### 3.5 Verified (recordings, with a **scratch copy** of the live calibration)
The Sep 25 recordings are effectively the setup before the 29 cm move, so
`check` on them against the Sep 28 calibration is a real "setup moved" test:
```
SETUP CHANGED: zone shift {front 4, back 4} -> {front 0, back 0}
old calibration:  FAIL empty (EMPTY never reached: the new room's motion
                  threshold trips on the old room), FAIL seat 4 (front row
                  wrongly shown on 100%), seats 3, 1, 2 pass
new calibration (replayed): all 5 steps PASS  ->  RECALIBRATED
```
Second `check`, setup unchanged: `PASS -- go live`. Quick and full self-tests
passed; `--steps` variants passed after the fixes below;
`test_presence_setup.py` 10/10; the live calibration file was confirmed
untouched throughout.

### 3.6 Bugs found and fixed
1. **Warm-up scored as missed occupants.** A fresh detector's 30 s warm-up
   (`UNKNOWN`) counted against the first step, so `--steps 3 empty` reported
   "MISSED OCCUPANT in 20/26". Fix: the first scene is held until the detector
   has warmed up ("warming up N s (hold this position)").
2. **EMPTY after an occupied step cannot happen in 45 s.** Clearing takes
   window + hold (~75 s) by design. Fix: an empty step that follows an occupied
   one automatically gets the full 100 s.

## 5. Gesture Recognition -- Review

### 5.1 Current implementation
| stage | implementation |
|---|---|
| recording (`x7_2s_record.py`) | choose one gesture, record N trials back to back (2.5 s, 40 FPS, first 34 bins) |
| features | 10 channels per sensor: amplitude, "horizontal" AoA, "vertical" AoA, second horizontal AoA, Doppler, amplitude skew |
| model | two-branch CNN, ~11.6 M parameters |
| evaluation | random 80/20 per-file split, best epoch chosen on it |
| live (`x7_2s_live.py`) | fixed raw-energy trigger (800), peak-centred 64-frame window, 3-seed ensemble, 45% confidence floor |

### 5.2 Data used
The gesture datasets were deleted from the working tree and the deletion
committed on Sep 24 (`893da5a`). The recordings were recovered **read-only**
from the initial commit (`8e21fb4`) into the session scratchpad; the working
tree and git state were not touched.
```
gesture_dataset_2s_new   591 recordings (476 in the 5 classes + 115 PINCH), (100, 2, 2, 2, 34)
4 subjects, 2 days:  subjects 2, 3 on 08-07; subjects 1, 4 on 08-11
each subject recorded each gesture as ONE contiguous burst of 20-25 (~2 min)
debug_captures/          315 live windows (Sep 4, Sep 8, Sep 10 s2, Sep 10 cal1)
```
Every gesture exists for every subject and on both days, so
leave-one-subject-out is a clean test (new person; for half the folds, a new day).

### 5.3 Does the CNN learn gestures or sessions?
Current architecture and augmentation, 30 epochs:

| input | random split | leave-one-subject-out |
|---|---|---|
| full | 87.4% | **73.7%** (S1 79.2, S2 76.2, S3 72.0, S4 67.2) |
| bins 0-19 only (behind the antenna, no hand) | 22.1% | 17.9% |
| physical bins 20-33 only | 87.4% | 73.3% |
| only angle channels | -- | **75.7%** |
| only amplitude channels | -- | 35.4% |
| only Doppler channels | -- | 36.6% |

* The random split overstates by ~14 points.
* No hidden session leak through empty bins (control at chance) -- unlike
  presence v2.
* The 20 behind-antenna bins contribute nothing.
* Angle alone carries everything that transfers to a new person; amplitude and
  Doppler do not. Largest confusion across people: PUSH_IN read as SWIPE_UD
  (30 of 125).

### 5.4 Physics measured on the corpus (no learning)
* **Hand position:** strongest bin 25 (0.41 m); per-recording peaks 0.33-0.90 m.
* **Left vs right:** sensor 1's horizontal phase change has the same sign for
  all 4 subjects; one fixed threshold separates them at 74-76%.
* **Push:** range centroid decreases for every subject (-3.6 to -11.2 cm vs
  ~0 for swipes). Doppler sign is inconsistent (fast pushes exceed
  +-0.41 m/s and wrap).
* **Up vs down:** no consistent cue. The sign of the phase change **reverses
  between the two recording days** (subjects 1, 4 vs 2, 3).
* **Inter-sensor timing lag** (which board sees the hand first): inconsistent
  across subjects at the August mounting -- not usable there.

### 5.5 Root cause -- each board is a one-axis line array
The code models each X7 board as having a horizontal (TX pair) and a separate,
perpendicular vertical (RX pair) baseline. Measured:

| test | expected if perpendicular | corpus | current mounting (cal1) |
|---|---|---|---|
| correlation of H-phase vs V-phase changes (shares a channel, biased) | ~0 | +0.98 / +0.98 | +0.99 / +0.99 |
| same, per-channel noise cancelled: (A+B) vs (C+D) | ~0 | **+0.95 / +0.95** | **+0.91 / +0.98** |
| phase change between the two cross elements (TX1RX0 vs TX0RX1) | large | **0.03 rad** | **0.03 rad** |
| outer pair / single baseline swing | -- | 2.33 / 2.00 | 1.72 / 1.98 |

(pairs are sensor 1 / sensor 2; single-baseline swing 0.62-0.98 rad)

The TX and RX baselines are parallel and equal, so the virtual elements
TX1-RX0 and TX0-RX1 coincide and the 2x2 array is a **3-element line**. Each
board measures angle along **one axis only** -- the direction its board is
rotated to. The "vertical AoA" channel is the horizontal one again; 6 of the
10 CNN channels are one measurement repeated three times. `x7_physics.py`
(`D_RX_V_M`, "vertical") models this incorrectly.

**Why it breaks across days:** a board rotated to angle alpha sees a left-right
swipe in proportion to cos(alpha) and an up-down swipe in proportion to
sin(alpha). Between a "\" and a "/" roll, cos(alpha) keeps its sign and
sin(alpha) flips -- exactly the corpus pattern (left/right consistent, up/down
reversed between days). A model learned on one mounting is silently wrong on
another, which matches the history: fine-tuning helped for a day and broke
after re-mounts, and 40 own captures beat 375 corpus recordings.

### 5.6 Error of ours
On Sep 10 we recommended re-mounting the boards "upright", based on axis-purity
numbers that assumed a separate vertical baseline on each board. That model was
wrong. If both boards now point along the same axis, **up/down may not be
observable from angle with the current mounting**. The 56 captures from the
current mounting show no clean up/down separation, but are too few to be sure.

### 5.7 Other weaknesses found
* Recorder: one gesture per burst -- every label is tied to one block of time.
* Model: 11.6 M parameters for 476 recordings.
* Live trigger: raw energy including static clutter against a fixed threshold
  -- depends on the room and setup.
* No calibration, setup check or self-test.

### 5.8 Recommendation
Rebuild the core, keep the edges.
* **Keep:** acquisition and frame pairing; peak-driven capture; energy-peak
  window centring.
* **Rebuild:** a one-axis-per-board antenna model (all 4 channels combined
  into one angle); features = angle rate per board, range change (instead of
  aliasing Doppler), energy envelope; 2-D direction by combining the two boards
  with their measured orientation; trigger on moving energy vs the
  behind-antenna floor; a small classifier (~10 physical features); shuffled,
  multi-person, multi-day recording; leave-one-person-out and leave-one-day-out
  evaluation only; a calibration (2 swipes each way to measure orientation) and
  self-test.
* **Hardware requirement:** the two boards' axes must not be parallel (e.g.
  rotate one 90 deg, or "\ /"). An in-plane rotation does not change range, and
  the presence features do not use absolute antenna phase, so presence is
  unaffected; run `check` once afterwards.

## 8. Lessons

**Verify the antenna model before interpreting angles.** Three sessions of
mounting changes and purity metrics were built on the assumption of a vertical
baseline that does not exist. One test -- do the two cross elements move? --
settled it in seconds.

**Test a correlation for shared-term bias.** The first H/V correlation (0.98)
was inflated by a channel common to both; the noise-cancelled version (0.95)
was needed before drawing a conclusion.

**Test a shortcut before recommending it.** Pairing seats would have halved
calibration time; the measurement showed it would also have corrupted the back
row.

**The test procedure can fail on its own.** Both self-test bugs were in how
steps were scored (warm-up, clearing time), not in detection -- found only
because the procedure was run end to end.
