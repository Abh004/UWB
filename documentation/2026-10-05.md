# Engineering Log — Dual-Sensor X7 Radar
**Date:** October 5, 2026

> **Correction (Oct 12):** this log's main conclusion is wrong. The September
> left/right labels were **not** reversed. Natural swipes captured the way live
> detection captures them were read correctly by the September model (10/12),
> and 0/12 by the relabelled model. The Enter-armed direction test captures a
> different movement pattern. The relabelling was undone, and
> `_trial_corrected` is not to be used. See README Section 4.5.

## 1. Session Objective

This session was all gesture recognition.

1. Find out why SWIPE_RL ("right → left") is not detected live.
2. Train on today's new recordings and compare with the deployed model.
3. Stop the move into a gesture's start position from being captured as the
   gesture.

**Outcome:** the cause was not the model or too little data. **The left/right
labels of all seven September sessions are reversed** relative to deliberate
swipes. The model learned left and right backwards. Live testing seemed to
confirm the reversed meaning, because live also captures the move into
position, and that move runs the opposite way.

A model-free direction test with 10 deliberate swipes exposed it. The
deployed model scored **1/10** on those swipes.

After relabelling 136 files, the corrected model scores **84.7%** held out
(the best so far), 90.1% precision with 78.9% of gestures recognised, and
**10/10** on the direction test. SWIPE_RL went from the weakest gesture to
62 of 76 recognised. The recorder now arms each capture with **Enter**.

The live test of the corrected model is still pending; it has not been
promoted.

## 2. Live: SWIPE_RL Not Detected

### 2.1 First live run (09-30 model, `--log gesture_live_rl`)
Ten SWIPE_RL attempts gave two correct SWIPE_RL reports. Two were reported
as SWIPE_LR (73.7%, 77.0%), and the rest were rejected as low confidence,
mostly leaning SWIPE_LR. Six SWIPE_LR attempts gave three correct reports.

### 2.2 First hypothesis: the move into position ("wind-up")
Angle change across each capture (board 1). Positive means the same
direction as the training SWIPE_LR:

| | angle change |
|---|---|
| live SWIPE_LR | +1.7 to +2.1 |
| live SWIPE_RL attempts | **+0.4 to +1.3 in 7 of 9** (LR-like); one −1.65, reported RL at 92% |
| training SWIPE_RL (median per session) | −0.21 to +0.09 |

The hypothesis: to swipe right → left, the hand first moves to the right,
which is a left → right movement. That movement trips the trigger and is
captured. The proposed fix was to hold still at the start position. Section 6
shows this was only part of the story.

## 6. Root Cause: September Left/Right Labels Reversed

### 6.1 Direction test (`direction_test/`, session G10051238)
The test was 5 SWIPE_LR and 5 SWIPE_RL. Each swipe was large and slow, with
Enter armed and the hand held still at both ends. It was recorded to a
separate folder and is **never used for training**.

```
python x7_gesture_record.py --host1 529 --host2 545 --gestures SWIPE_LR SWIPE_RL --per-gesture 5 --no-gesture 0 --block 1 --out direction_test
```

The deployed model read **8 of 10 as the opposite swipe**, and the recorder
flagged all 8.

### 6.2 Model-free angle direction
Energy-weighted slope of the unwrapped coherent angle across each window.

* **Up/down is consistent and strong in all 9 sessions:** SWIPE_UD has median
  slope −1.0 to −4.6 on board 1, SWIPE_DU +0.0 to +5.1, the same on board 2.
* **Left/right is weak and inconsistent everywhere,** including the direction
  test. There, board 2 separates them only weakly: SWIPE_LR positive in 5/5,
  SWIPE_RL negative in 3/5. Board 1 does not separate them.

Each board's single measuring axis (Sep 28) points mostly **up/down** at the
current mounting. Left/right has to come from weaker cues, such as which
board the hand passes first (the boards are 15 cm apart). Left/right is
therefore easy to get wrong, and up/down is not.

### 6.3 Which labels agree with deliberate swipes
Small models were trained on different label sets (2 seeds, 50 epochs) and
scored on the direction test:

| training labels | direction test correct |
|---|---|
| September sessions as recorded | **1/10** |
| today's sessions only (G10051022 as originally recorded) | 8/10 |
| today's sessions only (G10051022 swapped) | 9/10 |
| **September LR/RL swapped + G10051022 as originally recorded** | **10/10** |

Per September session, a reference model was trained on today's sessions
(original labels) plus the direction test, then scored on that session's
LR/RL captures:

| session | LR/RL captures | agree with label | **reversed** | other |
|---|---|---|---|---|
| G09291102 | 20 | 1 | 16 | 3 |
| G09291116 | 20 | 5 | 13 | 2 |
| G09291203 | 16 | 3 | 12 | 1 |
| G09291208 | 16 | 1 | 10 | 5 |
| G09301003 | 16 | 3 | 10 | 3 |
| G09301014 | 16 | 1 | 11 | 4 |
| G09301120 | 16 | 2 | 7 | 7 |
| **total** | **120** | **16** | **88** | **16** |

Every September session is mostly reversed.

### 6.4 Why the September labels are reversed (hypothesis)
The September recorder captured the first movement after GO. If that was
the move into the start position, each label holds the opposite movement:
for SWIPE_LR the hand travels right → left to reach the left. Live detection
has the same behaviour, so the reversed model looked correct on SWIPE_LR live
(it caught the wind-up), while real SWIPE_RL failed.

This is **not proven.** It does not explain why up/down was not reversed in
the same way. Possibly the hand rests near mid-height, so vertical wind-ups
are small; this has not been tested.

### 6.5 Relabelling
LR ↔ RL renamed in all 7 September sessions (120 files). The G10051022 swap
from Section 3 was undone (16 files), so that session is back to its original
labels. G10051151 is unchanged. In total 136 files were renamed; the log is
`models/_swap_LRRL_20261005_log.json`, with each (old, new) name pair.
Counts per session and gesture are unchanged.

## 13. Lessons

**Test against ground truth from outside the loop.** Training, held-out
evaluation and live use all agreed with each other for a week, because they
shared one reversed convention. Ten deliberate swipes, scored without the
model and by models trained on independent label sets, exposed it.

**When a "swap" makes data agree, ask which side is right.** Swapping
G10051022 made it consistent with September. It was consistent with the
wrong side.

**Look for physics behind a weak class.** SWIPE_RL was weak because the
mounting makes left/right a weak measurement. That made it the first place
a labelling error would show.

**Capture what the user intends, not the first movement.** The Enter trigger
separates "getting ready" from "the gesture".
