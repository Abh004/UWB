## 3. Physics & Mathematics Findings

### 3.1 Range scale was wrong by 2–5×  — FIXED
The README claimed 1.2 m (gesture) and 5.0 m (presence). At the X7's 6.5 mm/bin
baseband spacing the true figures are **0.22 m** and **0.72 m**.

Created [`x7_physics.py`](../x7_physics.py) as the single source of truth for all
constants (λ, bin length, antenna baselines) and shared DSP primitives. Nothing
elsewhere hardcodes a range or velocity any more.

### 3.2 The 339-bin fiction — FIXED
The presence recorder declared 339 range bins but **the hardware only ever populated
112**. All 501 recordings confirm this; the remaining 227 bins were zero-padding
written by the recorder itself.

This mattered because ~93% of bins sit at zero after MTI, and `log1p` is steepest at
zero — so the fabricated bins dominated every mean taken over the bin axis and
amplified injected noise far beyond real returns. `RANGE_BINS` is now 112, short
frames are rejected rather than padded, and legacy 339-bin files are auto-cropped.

### 3.3 Augmentation noise scaled to the wrong quantity — FIXED
`x7_2s_synthesize_data.py` sized additive noise against `np.std(raw)`, which is
dominated by static clutter that MTI subsequently removes. Noise arrived several
times larger than the surviving signal.

Now scaled to the **MTI residual**, with `σ/√2` per component so σ denotes the true
complex standard deviation.

```
synthetic / real feature ratio
  before   2.0x     (training distribution 2x the holdout it was scored against)
  after    0.999x   across all five occupancy classes
```

Also replaced `np.roll` (which wrapped breathing phase discontinuously across the
window edge, injecting a non-physical step) with a random phase offset.

### 3.4 Power vs amplitude domain — FIXED
Reflected **power**, not amplitude, scales with scatterer count. Occupancy features
now sum `|x|²` before log compression rather than mixing domains.

### 3.5 AoA notation conflated two apertures — FIXED
The horizontal phasor pairs TX0/TX1 (a **transmit** baseline); the vertical pairs
RX0/RX1 (a **receive** baseline). These are physically different apertures and were
documented under a single `d`. Both are one-way path differences, hence
`Δφ = 2πd·sin θ / λ`, not the two-way form.

### 3.6 Doppler aliasing was undocumented — FIXED
The inter-frame phasor wraps beyond `±λ·FPS/4`: **±0.41 m/s** (gesture, 40 FPS) and
**±0.10 m/s** (presence, 10 FPS). Now stated explicitly.

## 4. Data & Methodology Findings

### 4.1 Evaluation ran on training data — FIXED
`x7_2s_eval.py` evaluated the **entire dataset, including everything the model was
trained on**. This is the origin of the previously reported 93.77%. It now defaults
to the validation split; `--mode all` still reproduces the old behaviour but is
labelled a training-fit diagnostic. `--mode group` splits by recording burst.

### 4.2 Checkpoint selection peeked at the reporting holdout — FIXED
The presence trainer selected its best epoch on the same 100-sample holdout later
quoted as the headline — making that number a best-of-N order statistic. An early
noisy spike had inflated an 89% model to a reported 94%. Selection now uses a split
carved from training; the holdout is scored once, at the end.

### 4.3 Gesture data is burst-correlated — DOCUMENTED, NOT FIXABLE IN CODE
Each class was captured in only **4–5 bursts of ~25 back-to-back trials**, so trials
within a burst are near-duplicates and any per-file split leaves correlated samples
on both sides. Honest estimate via `--mode group`: **83.92%** (7-class model).

### 4.4 Silent data defects — FIXED
- 3 recordings in `4_people/` were missing the TX axis and were being dropped
  silently. Quarantined to `human_dataset_2s/_malformed/`.
- `4_people` had 1040 augmented samples vs 600 for every other class, because the
  generator only topped up to target and left stale files behind. It is now
  idempotent (clears output dirs first); all classes sit at exactly 600.

### 4.5 Housekeeping — FIXED
`requirements.txt` listed TensorFlow but **not PyTorch**, while every active script
is PyTorch. Corrected, with a note on the RTX 5090's `sm_120` wheel requirement.
`live_presence.py` (Keras, single-sensor, loads a model not present in the repo) is
marked deprecated.

## 5. Errors Introduced During This Session

These were mistakes made while "fixing" the above. Recorded because the cause of
each is instructive.

### 5.1 Destroyed the working gesture model — RECOVERED
**What happened:** The uncommitted working-tree `x7_2s_train.py` had `N_CLASSES = 6`,
so the README's 7-class documentation was declared stale. **This was backwards.** The
committed code and the deployed model were both 7-class; the 6-class script was an
unfinished work-in-progress. Acting on that, the model was retrained — overwriting
weights whose NOISE class **cannot be retrained** (no `G07_NOISE` folder exists).

**Root cause:** `git log` / `git diff HEAD` was never run before concluding the
documentation was wrong. One command would have prevented it.

**Recovery:** Original weights recovered from the local Git LFS store
(oid `dd0530e2…`, still intact). Verified by reproducing the original README's
confusion matrix exactly (93, 94, 90, 90, 94, 114).

### 5.2 Broke radar streaming — FIXED
A timestamp tolerance gate was added to frame pairing:

```python
dt = abs(buffer1[seq][1] - buffer2[seq][1])
if dt <= SYNC_TOLERANCE:      # 0.05 seconds
```

The SDK declares `timestamp: int` — an **integer tick count, not seconds**. Nearly
every pair was rejected and the frame queue starved; the live script hung at
`[WARMUP] 2/200`.

`SYNC_TOLERANCE` had been flagged as an unused-constant "discrepancy" in the audit
and was wired up without checking its units. It was unused for a good reason.
`x7_2s_record.py` is now byte-identical to the committed version; the presence
recorder records skew as diagnostics only.

### 5.3 Two rounds of live-gate changes chasing a self-inflicted problem
Adaptive thresholds, a motion-based gate, and a re-arm rewrite were all developed
against a model that had already been broken by 5.1. Reverted with the model.

**Lesson:** when a replay harness and real hardware disagree, capture the hardware's
actual data before theorising. The debug tool written at the end answered in one run
what four hypotheses could not.

## 6. Gesture Model Redesign (user request)

PINCH never triggered reliably on live hardware. On request it was **removed
entirely** and the system made continuous with no activation gesture.

Measured justification — restricting the old model's argmax to the five kept classes,
on identical recordings:

```
argmax over all 7 logits   96.8%
argmax over 5 kept logits  98.3%   <- PINCH/NOISE were drawing probability mass
```

### Final 5-class model — `models/best_model_2s_5class.pth`

Validation split (stratified 20%, seed 42): **94.74%**

```
Class        Prec    Recall     F1     N
SWIPE_LR    90.0%    94.7%   92.3%    19
SWIPE_RL    94.7%    94.7%   94.7%    19
SWIPE_UP   100.0%    89.5%   94.4%    19
SWIPE_DOWN  90.5%   100.0%   95.0%    19
PUSH_IN    100.0%    94.7%   97.3%    19
```

Single-sensor ablation: 68.4% (S2 only) / 60.0% (S1 only) — both far below the dual
figure, confirming genuine cross-sensor fusion.

The legacy 7-class model is preserved at `models/best_model_2s.pth`. Training now
takes `--checkpoint` so it cannot silently overwrite weights again.

### Capture is peak-driven, not fixed-length
The lag between crossing the motion threshold and the energy peak is **not constant**
— 1 to 97 frames, with per-gesture means differing (SWIPE_UP ~17, PUSH_IN ~34). A
fixed gather centres the window for some gestures and not others: at 50 frames,
PUSH_IN collapsed to 2/25 while swipes were unaffected. Sweeping the parameter only
traded classes against each other (best fixed: 68.8%).

The capture now tracks the running energy maximum and stops only once the gesture has
demonstrably peaked — energy falling for `DECAY_FRAMES` **and** `POST_PEAK_FRAMES`
elapsed since the peak, so the window's second half holds real data rather than edge
padding.

```
full live path (476 recordings)
  fixed gather   68.8%
  peak-driven    89.1%     PUSH_IN 2/25 -> 76/95
```

## 7. Live Recognition Diagnosis — **OPEN**

Symptom: gestures detected but frequently misclassified.

### Ruled out, by measurement

| Hypothesis | Evidence |
|---|---|
| Mounting angle changed | 10° costs 1%; even 30° leaves 79% |
| Sensor roll | Degrades PUSH_IN first — user's PUSH_IN works |
| Sensor order swapped | Would give 42.7%; observed pattern differs |
| Time-reversed buffer | Would give 2.0%; observed 57% |
| Window offset | ±8 frames costs ~1% |
| Peak localisation | Fixing it: 89.1% → 88.9%, i.e. not the cause |
| Amplitude scale | Normalising live windows changes nothing (59% either way) |
| Preset / frame assembly | Byte-identical to the working recorded configuration |

### Actual finding — from `x7_2s_debug_live.py`

Live windows match training on **geometry, timing and amplitude**:

```
                        recorded    live
range centre-of-gravity     26.6    27.0    same distance
motion span                 0.67    0.66    same duration
mean amplitude              0.90    0.76    within normal spread
```

The discriminator is **how far the hand travels across range**:

```
CORRECT live captures   5.2 bins = 34 mm
WRONG   live captures   3.8 bins = 25 mm     <- 9 mm shallower
recorded training       4.4 bins = 29 mm
```

Split by signal strength: **weak captures 36% correct, strong captures 72%.**

**Conclusion:** the pipeline is correct; the live gestures are physically smaller than
those the model was trained on. This is a data mismatch, not a software defect, and no
code change fixes it.

### Recommended next steps
1. Perform wider, more deliberate swipes at a constant distance — the user's own
   strong captures already reach 82–91% confidence.
2. For robustness to natural gesture size, record ~20 gestures per class as actually
   performed and fine-tune on the combined set. This is the durable fix.

Also observed: two captures triggered on the hand *approaching* (peak at window index
9 and 1 rather than 32). If frequent, the motion threshold needs raising for this
environment (`--threshold`).
